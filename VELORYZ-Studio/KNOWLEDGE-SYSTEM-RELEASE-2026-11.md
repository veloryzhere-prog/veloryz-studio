# VELORYZ Studio Knowledge System — Release Notes

**Edition:** 2026-11-21  
**Repository:** `veloryzhere-prog/veloryz-studio`  
**Project root:** `VELORYZ-Studio/`  
**Primary destination:** `https://veloryz.online/docs`

## What this upgrade includes

This release builds a connected, professional documentation experience on top of the existing VELORYZ Studio website without replacing the original VELORYZ identity, hero art or Motion Playground.

- **All documentation — `/docs/`:** A three-way destination choice (Help Centre, Studio documentation, all documentation), a searchable index of 152 guides, progressive article loading and original blue line-art illustrations with accessible CSS animations.
- **Help Centre — `/help/studio/`:** 20 articles on onboarding, project creation, support, AI, responsive design, delivery and troubleshooting.
- **Studio documentation — `/docs/studio/`:** 121 detailed operational/reference articles grouped into 18 documentation subjects. These cover actual production processes, security and governance, preview and publication, design systems and proposed editor implementation specifications.
- **Existing Studio service documentation:** 11 pre-existing source-backed guides remain under `/docs/<slug>/`, linked from the directory and editable via the protected article CMS.
- **Human-readable sitemap — `/sitemap/`:** Searchable directory of public site routes and every public documentation reference; includes animated original vector node diagram.
- **XML sitemap — `/sitemap.xml`:** Generated by the server from real route inventory, canonical URLs and published CMS visibility; `robots.txt` advertises it and excludes administrative/private paths.
- **Footer and header:** Useful Links targets `https://veloryz.online/docs`; footer connects all three documentation destinations, the human sitemap and XML sitemap.
- **Protected CMS:** `/admin` → Documentation edits article titles, summaries, Markdown, editorial status and public visibility through the existing Save draft → Preview → Publish workflow, with version history.

## Content accuracy and editorial policy

All 141 Studio/Help entries replace the former generic “Documentation status: Product documentation blueprint” placeholder with detailed purpose, audience, preparation, topic-specific operating procedure, configuration, acceptance checks, troubleshooting, recovery and related links.

The source specification contains numerous visual-editor controls that are **not established as deployed customer-facing Studio features**. Documentation is explicit about actual public workflows (`/create/`, `/pricing/`, `/book/`, `/contact/`), owner CMS administration, the private portal, optional integrations and additional capabilities that need development or operator verification. It must not promise an unverified editor, payment system, account entitlement or AI provider.

An article's editorial label **Studio field guide** means practical reference content, **not** a certification that every described optional capability is deployed. `reviewed` is reserved for human editorial review recorded in the CMS.

### Performance and motion

The directories load only the ~52 KB compact docs index, rather than the full large handbook. Reader routes lazy-load one of 19 cached topic collections. Visible directory cards paginate in batches of 24. Images are inline original SVG; motion uses CSS transforms and opacity, and respects `prefers-reduced-motion: reduce`.

### Security and publishing

Article Markdown is rendered as escaped HTML and supports approved safe links. CMS overrides are server-validated, remain draft until explicitly published, and are not equivalent to executing arbitrary scripts. The runtime injects `window.STUDIO_STATE` for **versioned** application scripts; previously the bootstrap's unversioned script selector prevented initial state embedding.

The XML sitemap excludes CMS-hidden documents and private routes. Every guide should be inspected before publishing high-stakes instructions, especially for payment, privacy, ownership, domain operations, auth and integration credentials.

## QA and release process

Run from `VELORYZ-Studio/`:

```bash
corepack enable
corepack pnpm install --frozen-lockfile
node tools/test-documentation.mjs
corepack pnpm exec tsc --noEmit
corepack pnpm build
```

The root GitHub Actions workflow `.github/workflows/veloryz-documentation.yml` is configured to run these gates for applicable pushes and pull requests.

Additional integration smoke testing should cover: `/docs/`, both nested reader branches, article search, print/copy-link controls, `/sitemap/`, `/sitemap.xml`, admin CMS save/preview/publish, hidden-document HTTP status and sitemap exclusion, forms and mobile layouts, and absence of regressions to original VELORYZ animations.

**Important:** A GitHub commit does not prove that production hosting deployed it. Confirm the active hosting deployment, check the live response status for each destination, verify the running CMS backend, and only then announce the release as publicly live.

## Ongoing maintenance

When a feature ships or a policy changes, update the authoritative source and any corresponding topic-specific content, keep the index and 19 chapter files synchronized, verify internal links, and publish the reviewed CMS revision. A future release should automate regeneration of the compact index, chapter files and server route map from a single canonical source.
