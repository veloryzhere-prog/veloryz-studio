# R51.1 — Studio OS 4.0 foundation

The approved design direction is a light, compact, operational SaaS shell with neutral canvas, white navigation and indigo accent. All twenty legacy console destinations are mapped exactly once into seven task groups. Existing backend APIs, authorization, publishing versions, project records, AI settings and private files remain unchanged. The shell now renders a new sidebar and contextual top bar, with compact desktop rail, mobile drawer, keyboard shortcuts, focus handling, shared surface/form/button/dialog styles and explicit website-draft versus operational semantics. Old route handlers and compatibility CSS remain until their dedicated R51 sub-releases. The dashboard, action inbox, CRM, finance, AI lab, visual CMS, media, marketplace, campaigns, docs and infrastructure redesigns are R51.2–R51.11. Dark mode and authenticated screenshot certification are not included in R51.1. The reference images are design inspiration, not pixel-perfect clones.

Release check: exact deployed owner shell, both versioned assets, private/noindex headers, denied anonymous admin state, and absence of admin-specific styling from the public homepage. Local developer preview injection also accepts versioned admin script URLs.

## R51.2 — Executive dashboard and action inbox

Owner-only Overview and new Action Inbox share a read-only, separately loaded dashboard module. The seven existing groups now contain 21 destinations (all 20 legacy routes plus inbox). Counts use existing authenticated APIs; enquiries use server total, client/review/payment counts are bounded by returned records. The first 25 new enquiries and at most 12 project details (three concurrent) generate actions, with explicit coverage. Client directory capped at 200, item/message results at 150, payment records at 100. Private body text, contact fields, payment tokens and credentials are not retained in dashboard state. Source records remain editable in their respective consoles. Service health indicates read-only availability/configuration, not live model or SMTP tests. No synthetic production stats or write requests. Authenticated visual QA and aggregate unlimited inbox are outstanding.

## R51.3 — CRM and delivery pipeline

Enquiry table/pipeline, local page search/sort and follow-up ordering retain the real status/version and acceptance editors. Server pagination remains 25 records. Client delivery pipeline is grouped by actual workspace status; opening a card uses the existing private client console. A database-wide owner-only summary replaces the twelve-project dashboard sampling when available; first 200 client action records are shown with full count, and fallback coverage is explicit. No automatic email, payment, invitation or status changes. Authenticated UI acceptance remains separate.

## R51.4 — Finance desk

Owner-only full-database payment totals, server search and status filters with 50-row pages, CSV export of current page (formula protection and no token), receipt-reference reconciliation and versioned private audit trail, explicit agreed-budget records linked to existing enquiry references. Existing payment request links are retained. No automatic collection, gateway-confirmed receipts, bank balance or tax invoice. Older records have no invented evidence. Budget list returns up to 200 recent records; budget less verified is a planning difference. Legacy API status updates remain compatible; new finance form requires receipt evidence. Authenticated write tests use synthetic fixtures only; no real payment records changed during implementation.

## R51.5 — AI Intelligence Center

Six operational views: four saved assistant profiles, five published adviser briefs, shared provider settings and connection test, custom-question saved-profile playground, public knowledge retrieval inspector, and 30 UTC calendar days of recorded outcomes. Existing independent encrypted credentials and same-provider Help fallback remain unchanged. Owner tests share existing limits and usage counters; source-only tests make no inference call. Tests show actual model, route, status, saved profile revision and server elapsed time when reported. No private records or secrets should be entered. No transcript storage or billing/token estimates are added. Switching AI tabs/profile or refreshing editors warns about unsaved edits; this is not global draft persistence. Authenticated browser certification remains outstanding.

## R51.6 — Visual Website CMS

Page-oriented editor for ten existing CMS areas, with device-width read-only saved draft preview, explicit legacy versus current homepage support, related editor links and whole-draft publication disclosure. The current editorial home preview uses the same server renderer as the public homepage, not the legacy SPA. Draft preview requests require owner authorization, use an allowlisted view, no-store/noindex and a script-only sandbox without forms or same-origin privilege. Dynamic media/services may be unavailable in the isolated canvas. No drag-and-drop layout builder or unsaved live DOM sync; code-controlled visual assets remain unchanged. Saving and publishing preserve newer unsaved edits that arrive during the network request. No actual site content was published by this implementation.
